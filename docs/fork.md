# Fork customizations

This fork retains the upstream Pi Web package name and version. Its upstream release base is **v0.18.0**, commit `2daa0d1`.

**Integration status:** this document describes the v0.18.0 merge candidate and its intended compatibility boundaries. It is not a deployment record or a claim that this candidate has been released, activated, or fully validated.

## Application changes

- Live session rows expose only the **⋯ menu**, not a one-click archive button, to reduce accidental archiving. Archive remains in the menu with Undo; the archive view retains its desktop one-click Restore. Upstream shared read times, per-browser unread markers and automatic sidebar reveal are retained.
- The ordinary tool menu offers only **read / build / full**, display labels for upstream internal ids **`read-only` / `default` / `full`**. The labels are display-only, not a new parent-session execution policy; the fresh composer's initial selection is a separate fork default. With no browser preference, a new conversation starts in **build** (`NEW_SESSION_TOOL_PRESET = 'default'`), explicitly selecting the four upstream built-ins `read`, `bash`, `edit`, and `write`, rather than upstream first-use `configured`. Later fresh conversations follow the browser's most recent explicit selection. `configured` and Chat only (`none`, also called chat-only) are hidden as active menu choices, not removed from the runtime, history, preference storage or API. Existing sessions restore their actual state without migration, including `configured` and `none`; hidden current values must still be shown truthfully rather than mislabeled as read or build. This browser first-use default does not force legacy API requests with no tool selection into build: upstream configured/default resolution remains compatible. Side chats retain their upstream fixed reduced tool boundary.
- Ordinary parent-session tools, extensions and MCP follow upstream behavior. **read is a built-in read-only tool preset, not a strict read-only execution mode or sandbox**: it adds no fork-wide tool allowlist or blanket extension/MCP prohibition. Upstream MCP read-only-hint handling and other upstream resource/trust rules still apply. There are no fork parent-mode instructions, Send-time mode drafts or family-wide Stop behavior; preset changes and Stop use upstream semantics.
- Background running conversations receive bounded history prefetch using the existing sidebar poll, without extra SSE streams or starting sessions. Hidden/offline pages pause prefetch. History revisions include the effective upstream notices switch: toggling it invalidates cached messages, while unchanged validation reads only the switch and skips notice scans. Notices settings reads are bounded and non-blocking for both global and project files. Foreground/background read ordering and confirmed model/effort-write fences prevent stale replies from undoing newer state.
- Reasoning controls use one capability-driven menu. Supported off/on/effort options can save exact SDK-native per-model defaults. Ordinary selections remain session-scoped; model changes restore the target model's saved default without transient display mismatches. Reselecting the current model refreshes saved definitions without reapplying its default effort; native capability clamping and newer explicit effort changes remain authoritative.
- Completion chimes and browser notifications require an observed SDK run and fire exactly once per logical completion after it settles or is confirmed idle. Handled commands with no run announce nothing; a command handing off a run cannot announce early on `prompt_done`. Upstream best-effort cross-page chime claims remain an additional deduplication layer, not a replacement for that completion gate.
- Page titles retain Pi Web branding and the session title. The `steer_subagent` description explains completed-run steering errors without prescribing a result-retrieval follow-up.

## Subagent-specific compatibility policy

The fork's subagent role/resource policy is retained separately from the ordinary parent's upstream tool behavior:

- **read** (`read-only`, formerly labeled plan) admits only scout/planner; **build** (`default`) admits scout/planner/worker/reviewer. Scout/planner are forced to their read-only built-ins in both presets; worker/reviewer keep their role's built-in tools in build. **full** follows the original profile behavior. An unpinned `configured` parent keeps the fork's original default-build subagent admission rule; that does not turn its own tool state into build.
- Limited children keep an immutable resource snapshot/ceiling, with no extensions, MCP or skills except optional explicitly vetted webfetch. Resume and steering recheck the current parent's permissions as well as the child's saved ceiling; later parent changes cannot silently widen a limited child. These are subagent execution/resource constraints, not an operating-system sandbox or a parent-wide tool allowlist.
- Upstream trust and profile gates apply alongside that ceiling: a newly created child uses parent trust, reopening uses child trust, and project profiles load only for trusted projects. Trust is not inferred from the menu label, and neither trust nor a project profile bypasses a limited child's role/resource ceiling.
- When the built-in subagent host is disabled, the original external dispatcher remains a compatibility path for this subagent policy. Its vetted subagent/webfetch implementations are required for that path, **not** a prerequisite for ordinary read/build parent tools. When enabled, the built-in host supersedes the external Web dispatcher without changing terminal configuration.

Design details and regression boundaries are in [tool presets](agents/tools.md), [built-in subagents](agents/subagents.md), [side sessions](agents/side-sessions.md), [sessions](agents/sessions.md), [client completion behavior](agents/client-platform.md#completion-sound), and [models](agents/models.md).

## Source and deployment separation

This repository contains application code, portable tests, and generic documentation. Machine-specific build/activation helpers, service launchers, deployment records, real configuration, credentials, and sessions are maintained **outside this repository**.

Use the development and test commands in the [README](../README.md). Do not run production builds over a live development or deployed `.next` directory. Publishing this source does not deploy a service or publish an npm package. The npm publish workflow is restricted at job level to `agegr/pi-web`; tags on personal forks cannot publish under the retained upstream package name.
